# sovetnikOS 0.6

Минимальная учебная ОС для x86 (32-bit protected mode). Собирается и
запускается под Linux. Умеет: рисовать текст в графическом режиме через
линейный фреймбуфер, работать с файлами и папками в RAM-диске, читать и
писать секторы на ATA-диск, обрабатывать прерывания через GDT/IDT/PIC/PIT.

## Что внутри

- NASM bootloader с Multiboot-заголовком (с поддержкой видеорежима)
- C kernel (`kmain`)
- Загрузка через GRUB (`grub-mkrescue` + `xorriso`)
- Линейный фреймбуфер **1024×768×32** (VBE), встроенный шрифт 8×16
- Fallback в VGA text mode, если GRUB не отдал framebuffer
- **Своя GDT** (kernel code `0x08`, data `0x10`)
- **IDT** + **PIC** (remap IRQ0..15 → векторы 32..47) + **PIT** (100 Гц)
- PS/2 keyboard polling + обработка стрелок, Home/End/Delete
- Парсинг карты памяти Multiboot (`mmap`)
- Bump allocator (`kmalloc`) + heap сразу за ядром
- **RAM-диск** (ramfs): файлы, папки, `.sov`/`.sp`, до 32 объектов
- **initrd** в формате ustar, грузится GRUB как модуль
- **ATA PIO драйвер** (primary master): чтение и запись секторов
- **Shell** с историей команд, цветным выводом и горячими клавишами

## Требования (Ubuntu / Debian / Linux Mint)

```bash
sudo apt update
sudo apt install nasm gcc binutils make \
                 grub-pc-bin grub-common xorriso \
                 qemu-system-x86
```

## Клонирование и сборка

Склонируйте репозиторий и соберите ISO:

```bash
git clone https://github.com/demenkovmaks42-cloud/SovetnikOS.git
cd SovetnikOS
make
```

Если вы уже внутри клонированной папки — просто:

```bash
make
```

Собираются:

- `build/kernel.bin` — ядро
- `build/initrd.tar` — образ initrd (ustar) из папки `initrd/`
- `build/sovetnikOS.iso` — загрузочный ISO

## Запуск

```bash
make run
```

или без ATA-диска:

```bash
make run-nodisk
```

или вручную:

```bash
qemu-system-i386 -cdrom build/sovetnikOS.iso \
                 -drive file=disk.img,format=raw,if=ide -vga std
```

При первом `make run` автоматически создаётся `disk.img` (16 МБ) для
ATA-диска. Для выхода из QEMU: `Ctrl+Alt+G` (release mouse), затем
закройте окно.

## Формат файлов

- **`.sov`** — текстовые файлы пользователя (заметки, документы, скрипты).
  Выводятся как текст.
- **`.sp`** — системные файлы. При `cat` выводятся и как текст, и как hex.
- **Папки** — обычные директории, помечаются `[dir]` в `ls`.
- **Прочее** — любые файлы без расширения из списка.

Расширение `.sov`/`.sp` добавляется автоматически, если его нет в имени:
`sov note` создаст `note.sov`, а `sov note.sov` — то же самое.

В `ls` разные типы помечаются цветом:

- `[dir]` — голубой
- `[sov]` — зелёный
- `[sp]` — красный

```

linker.ld     карта линковки ядра
grub.cfg      конфиг GRUB
Makefile      сборка
disk.img      образ ATA-диска (создаётся автоматически, не коммитить)
```

## Как работает память

1. GRUB передаёт в `kmain` Multiboot-структуру.
2. Ядро читает `mmap` (флаг `1 << 6`) и суммирует доступную RAM.
3. Heap начинается сразу за ядром (символ `_kernel_end` из `linker.ld`)
   и заканчивается за страницу до верхней границы RAM.
4. `kmalloc(size)` — простой bump allocator: двигает указатель вперёд
   с выравниванием по 4 байта. Освобождения памяти нет (учебная ОС).

## Как работает файловая система

1. В `grub.cfg` указан `module /boot/initrd.tar`.
2. GRUB загружает `initrd.tar` в память и передаёт адрес в
   `mbi->mods_addr` (флаг `1 << 3`).
3. Ядро вызывает `tar_init(addr)` — парсер формата **ustar**.
4. Затем `ramfs_load_initrd()` копирует файлы из tar в RAM-диск.
5. Дальше работа идёт только с ramfs: файлы можно создавать, читать,
   изменять, удалять. Папки — это объекты с полным путём (`/docs/a.txt`).
6. При перезагрузке RAM-диск стирается; `initrd` восстанавливается заново.

## Прерывания (GDT + IDT + PIC + PIT)

Порядок инициализации в `kmain`:

1. `gdt_init()` — загружает свою GDT (kernel code `0x08`, data `0x10`).
2. `idt_init()` — заполняет IDT шлюзами для IRQ0..15 (векторы 32..47).
3. `pic_init()` — remap IRQ0..15 → векторы 32..47, разрешены только IRQ0/IRQ1.
4. `pit_init(100)` — таймер на 100 Гц.
5. `sti` — включает прерывания.

`gdt_init()` **обязательно** вызывается до `idt_init()`, иначе селектор
`0x08` в шлюзах будет невалидным, и первое же прерывание уронит систему.

IRQ0 (таймер) увеличивает счётчик, `ticks` в shell показывает его значение.

## ATA

Драйвер `drivers/ata.c` работает с **primary master** через PIO:

- `ata-info` — IDENTIFY, читает модель и число секторов LBA28;
- `ata_read_sectors(lba, count, buf)` — чтение секторов;
- `ata_write_sectors(lba, count, buf)` — запись секторов.

QEMU подключает `disk.img` как IDE-диск при `make run`.
Файл создаётся автоматически (16 МБ) при первом запуске.

**Важно:** сейчас ATA работает на уровне сырых секторов. Полноценной
файловой системы на диске пока нет — файлы в ramfs **не сохраняются**
между перезагрузками.

## Как добавить файл в initrd

```bash
echo "мой текст" > initrd/myfile.sov
make
```

Файлы кладутся плоско (без подпапок) — так проще парсеру.

## Ограничения

- RAM-диск: до **32 объектов** (файлы + папки), по **4 КБ** на файл.
- Нет рекурсивного `rmdir` — сначала удалите вложенные файлы.
- `cd ../docs` не поддерживается, только `cd ..` и `cd docs`.
- Шрифт framebuffer содержит только ASCII 32–126, без кириллицы.
- ATA: 28-bit LBA, PIO, только primary master.
- `cwd` не влияет на initrd — файлы всегда загружаются в корень `/`.

## Идеи для развития

- Файловая система на ATA (FAT16 или свой формат) — сохранять файлы
- Кириллица в шрифте 8×16
- Цветной вывод статусов в shell (в `[ OK ]` / `[FAIL]`)
- Простой графический редактор (линии, прямоугольники, окна)
- Клавиатура через IRQ1 вместо polling
- Многозадачность и переход в ring 3
- Системные вызовы через `int 0x80`
